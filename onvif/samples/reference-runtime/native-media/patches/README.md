# Private classic RTSP qualification patch

**Candidate, not upstream-reviewed or distribution-ready.** Apply only to the
locked 1.28.7 source commit `070125524a8422e29d3b69a372ed4f62fd343ffa`.
`prepare-source.py` checks every pristine Git blob before applying the patch.
Only the seven-source RTSP library and five-source classic RTSP plugin are
rebuilt against the exact SDK; this is not a monorepo/Cerbero rebuild.

`classic-rtsp-p0.patch` preserves the original v1 fixture behavior.
`classic-media-v2.patch` layers the explicit v2 reference policy; its current
private ABI marker is **classic-media-v2-scoped-auth-4**, not an upstream ABI.
The v2 worker accepts actual private credentials and separately scoped
HTTP/HTTPS Digest, local interface/origin/realm/principal policy, strict TLS
validation, authorized redirects without downgrade, and native control receipts.
UDP checks advertised transport and actual RTP/RTCP sender address/port before
RTP-manager processing; it does not rely on SDP source text alone.

Native PAUSE/PLAY scheduling avoids the interrupted-loop CMD_WAIT race.
Recorded seek remains a real native operation, dispatched off the IPC loop;
a private interrupt wakes pending native I/O on CLOSE. Successful scheduling
never creates an IPC acknowledgment: accepted wire responses do. Backchannel
uses the native send path and reports real errors rather than fake success.
The stream-start activation correction uses the intended per-stream pad.
JPEG SOF reconstruction and terminal access-unit drain are bounded worker
helpers around existing depay/decoder elements, not new codecs/transports.
Remaining JPEG segment-before-caps warnings are retained in qualification.

The independent Python fixture remains the original stdlib server. Its
full-duplex TLS object is serialized because concurrent receive/media threads
exposed Windows WSAEWOULDBLOCK; this is a fixture I/O correction, not disabled
TLS validation or a replacement server stack.

The P0-only discussion below is historical; see `onvif\support\notes\onvif-media.md` and
`onvif\support\reports\onvif-media-qualification.md` for the actual v2 contract and tested cells.

The original source has two coupled gaps:

| Source | Observed behavior |
| --- | --- |
| `gst-plugins-base/gst-libs/gst/rtsp/gstrtspdefs.c:604-641` | Legacy public response API supports RFC 2069 MD5 only. |
| `gst-plugins-base/gst-libs/gst/rtsp/gstrtspconnection.c:1325-1400` | `add_auth_header` passes a null algorithm and never includes qop/nc/cnonce. |
| `gst-plugins-good/gst/rtsp/gstrtspsrc.c:6980-7023` | Challenge parsing overwrites Digest parameters while walking alternatives; it also accepts Basic. |

The private helper selects only declared combinations: legacy MD5 without qop,
MD5/auth, and SHA-256/auth. SHA-256/auth ranks above MD5/auth, then legacy MD5.
Unsupported algorithms, auth-int-only, session algorithms, userhash, non-ASCII
credential/challenge data, and ambiguous/injected parameters are rejected.
Basic is deliberately **not selected in this qualification plugin**. This is
not a transparent replacement for stock `rtspsrc` applications needing Basic.
TLS validation code is unchanged; the P0 worker does not yet expose TLS.

The response hashes the URI exactly as serialized and includes the selected
qop, eight hexadecimal nonce-count digits, and cnonce in the RFC order.
BCrypt supplies the Windows cnonce; nonce count is per connection/nonce, is not
reused when the same nonce is challenged again, and refuses wrap. Stale nonces
reset the count; algorithm/qop downgrade and realm changes on an authenticated
connection fail before serialization. Each RTSP operation has at most three
attempts. RFC 2617 and RFC 7616 section 3.9.1 literal vectors are independent
oracles, not hashes generated by the fixture or helper.

`p0-after-response` is a **private gate signal**, added so the worker can observe
actual PLAY/TEARDOWN status and returned CSeq/Range. It is not an upstream public
API proposal. RTSP redirects are rejected before the source can follow them.
The library exports a private revision marker for startup mismatch detection.

The exact-frame replay gate also found a separate clock-domain problem at
`gstrtspsrc.c:6281-6294`: the first/discontinuous interleaved packet receives a
**running-time receipt DTS**, even when the ONVIF segment is in nanoseconds since
1900. The measured first packet had DTS about 0.19 seconds while its segment
started at 3998462400.25 seconds. This lost the first JPEG frame (and, in live
RTP-manager mode, the first packet of every replay track). The additional
one-condition patch suppresses only that implicit receipt DTS in ONVIF mode.
Explicit `tcp-timestamp` requests retain their upstream behavior. It does not
invent a decode/capture timestamp: unknown DTS stays unknown, receipt monotonic
time is separate IPC provenance, and the native NTP extension is preserved.
The worker uses the documented `is-live=false` mode for TCP `Rate-Control:no`.
RTP probation was investigated and rejected as the cause; its default is intact.

## Review and vendoring conditions

Preserve all upstream notices. The original `.c`/`.h` sources remain unchanged
in the task-local source cache; patched copies live in the owned build tree.
Keep the patch, helper sources, source hashes and exact build/runtime artifacts
together for review. No patch or private code is submitted anywhere by this task.
The repository's original-code license and any binary redistribution permission
are not established by this gate.

Before general availability, obtain upstream/maintainer review for challenge
selection, quoted strings, ASCII/UTF-8 policy, Authentication-Info/rspauth,
nonce state across reconnects/tunnels, concurrency, and platform entropy.
Replace the private Digest-only build policy with a properly reviewed explicit
authentication-policy API, without restoring silent Basic/downgrade behavior.
Review the response-observation API and test the actual supported TLS/tunnel
paths, including the ONVIF receipt-DTS correction above. A passing local wire gate does not settle these packaging/API reviews or
claim complete RFC 7616 / ONVIF conformance.
