# Native P0 and IPC v2 dependency boundary

This directory is a **local reference runtime and qualification gate**, not a
certified or approved distributable media package.
`dependencies.lock.json` pins GStreamer 1.28.7 and its official Windows MSVC x64
distribution. No npm hook, global package install, firewall change, or camera
access is part of this gate.

## Explicit task-local SDK acquisition

Use an existing exact-version SDK first. After a missing-SDK failure, read the
locked upstream notice and licensing advisory before running:

```powershell
.\native\onvif-media\tools\fetch-sdk.ps1 -AcceptUpstreamLicenses -ProvisionPortable
```

This downloads and checks the published SHA-256 before execution. It uses the
upstream installer's **portable mode**, not an ordinary user/system installation.
The pinned Cerbero `data/inno/base.iss` implements `/portable=1`;
`cerbero/packages/windows/inno_setup.py` disables uninstall registration,
environment/installation registry tasks, VS templates, and the VC redistributable
in that mode. `/CURRENTUSER`, empty tasks, and `/NORESTART` are also explicit.
All SDK files and the extraction log go under the named task-local TEMP directory.
Nothing changes the parent process or persisted environment.

If a provisioned SDK becomes incomplete, do not overwrite a potentially
concurrently modified cache. Select a new `-TaskRoot` and optionally reuse the
original `-CachedArchive`; its locked SHA-256 is checked again before extraction.
The September 16 continuation reuses the already-extracted
`onvif-native-p0-runtime-c82da58f-20260916\sdk`; the preserved upstream cache
remains separate. Supply explicit `-SdkRoot` and `-SourceRoot` parameters,
not a historical session-specific default. No existing cache was deleted or
overlaid. The cached installer still matches the approved SHA-256 and is
NotSigned; checksum verification is not publisher-signature verification.

The current upstream Python wheels were considered, but their packaging path
uses runtime file lists, not development file lists. Installing the aggregate
`gstreamer-bundle` would also pull unrelated GPL/restricted plugins and Python/GTK
bindings. They are not dependencies of this C worker.

## Licensing and provenance

GStreamer's core and the classic RTSP/RTP/app libraries use LGPL terms; retain
each file's original notices. The SDK contains separately licensed components.
The package-level description is **not** proof that every decoder is LGPL or
cleared for redistribution. Local qualification is not a new license assignment
to this repository and does not authorize publishing a binary bundle.

Any patched native library needs its exact upstream source, minimal patch,
build commands, source and binary hashes, preserved notices, and an upstream
review record before distribution. No private source or credentials are uploaded.
Codec patents/commercial licensing and corresponding-source/relinking obligations
remain packaging gates. No GPL/nonfree decoder is implicitly approved by the
process boundary.

The retained P0 fixture targets synthetic JPEG/G.711. The v2 codec gate adds
actual H.264 constrained-baseline 8-bit, H.265 Main 8-bit, MPEG-4 Simple,
AAC-LC and ONVIF JPEG SOF reference streams, with complete pixel/sample/packet
oracles. This is not arbitrary profile or cross-transport codec coverage.
Existing SDK encoders are test-only: OpenH264 (BSD), x265 (GPL), libav and
raw parsers are not copied into the worker bundle. Do not ship the x265
fixture tool as a runtime dependency.

Codec tools use a separate eight-plugin test directory and private registry;
they never scan the SDK's unrelated Python/GTK/proxy plugins. Native CTest
units also select private plugin/GIO paths and a build-local registry.
The first replacement-SDK ALL run preserved a real tool-scan failure before
this isolation correction; it is not replaced by historical codec passes.

The selected SDK supplies GLib 2.82.4, libxml2 2.14.5 (MIT-style terms), and
libjpeg-turbo 3.1.0. `gstjpeg.dll` imports `jpeg8.dll`; the inspected libjpeg-turbo
notice describes IJG/BSD/zlib obligations. This software is based in part on the
work of the Independent JPEG Group. This attribution does not replace the
complete notices/corresponding-source audit required before distribution.
The synthetic RFC 2435 JPEG, G.711, and XML test data are generated by this
directory's fixture code; no third-party camera capture or copied media asset
was used.

For the build and all explicit native/loopback/Node IPC tests, run
`tools\build.ps1 -SdkRoot <exact-sdk> -SourceRoot <locked-source-cache> -Test`.
It reuses CMake/Ninja/MSVC/Python already on the host. The test option runs
the unfiltered current CTest cohort and records source/SDK/binary stability;
old targeted JSON files cannot stand in for a fresh ALL run. Node is test-only:
the final gate used existing Visual Studio-bundled Node 24.12.0, not a new
installation or a Node package modification. Supply `-NodeExecutable` if needed.
The measured support matrix, exact IPC contract, warnings, and remaining
promotion blockers are in `spec\onvif-media-qualification.md` at the repository root.

The v2 process loads only its private selected plugin/GIO directories and
private registry. Runtime SHA-256 inventories identify the actual files, not
a bit-reproducibility or redistribution claim. Scoped credentials enter a
private one-frame pipe; the preserved v1 fixture's synthetic selector is not
part of the v2 credential API.
